# 会记 Minutes · AI 会议纪要 App — 项目说明

> 上传录音 → 自动转写 → 结构化摘要 → 提取待办 → 看板跟进
> 演示账号：`demo@minutes.dev` / `minutes2026`

---

## 一、项目简介

**会记 Minutes** 面向 5–30 人的研发 / 产品团队，解决周会、复盘会「无纪要、待办不落、开完就忘」的问题。一段会议录音上传后，系统自动完成：

1. **异步语音转写（ASR）**：本地 faster-whisper 离线识别（免费、可无网运行），按时间戳分段，点击分段跳转音频对应位置；
2. **结构化摘要（LLM）**：生成议题、关键结论、决策、风险与待办，摘要保留版本历史，可重新生成与回退；
3. **行动项提取与看板跟进**：待办自动带出负责人 / 截止时间 / 优先级，三列看板拖拽、跨会议按人聚合、逾期一键提醒；
4. **团队协作**：四角色权限（Owner / Admin / Member / Viewer）、会议身份（主持 / 记录 / 参会 / 旁听）、资料共享、评论、只读分享链接、操作审计。

核心处理链路：`uploaded → transcribing → summarizing → done / failed`，失败可从断点重试，已完成阶段不重复执行。

前端内置 MSW Mock（49 个接口的浏览器内实现），**零后端、零 API Key 也能完整演示全链路**；也可切换连接真实 FastAPI 后端跑本地离线语音识别与云端大模型摘要。

## 二、技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | Next.js 15 (App Router) + React 19 + TypeScript 5 + Tailwind CSS 3 | 页面、上传、播放器联动、看板、PWA |
| 前端数据 | TanStack Query 5、Radix UI、dnd-kit（拖拽）、wavesurfer.js、Zod | MSW 提供浏览器内 Mock |
| 后端 | Python 3.11 + FastAPI 0.116 + Pydantic v2 + SQLAlchemy 2 + Alembic | 49 个 REST 接口，自动生成 `/docs` |
| 认证安全 | JWT（HS256，access 1h / refresh 30d 旋转）、PBKDF2 口令哈希、RBAC | 登录失败限流 |
| 异步 | Redis 队列 + 独立 Worker 进程 | 未配 Redis 自动降级进程内 asyncio |
| 数据库 | PostgreSQL 16 + pgvector | 14 张表，GIN 全文索引 + HNSW 向量索引；未配库降级内存存储 |
| 对象存储 | MinIO / S3（私有桶 + 预签名 URL） | 未配置回退本地磁盘 |
| AI | faster-whisper small（本地转写）/ 通义千问 qwen-plus（摘要，可选） | 未配置回退内置演示模板 |
| 实时通信 | SSE + Redis Pub/Sub | 转写 / 摘要进度实时推送 |
| 测试 | Playwright（20 条 E2E）、pytest（13 条）、Vitest | Mock 与真实后端两种模式均通过 |

## 三、环境配置

### 3.1 环境要求

| 软件 | 版本 | 用途 |
|---|---|---|
| Node.js | 20+ | 前端开发与构建 |
| Python | 3.11+ | 后端与 Worker（只跑前端 Mock 不需要） |
| Docker Desktop | 24+（可选） | 仅 Docker 全栈方式需要 |

### 3.2 依赖安装

```powershell
# 前端
cd apps/web
npm install

# 后端
cd apps/api
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 3.3 关键环境变量

| 变量 | 说明 | 默认 |
|---|---|---|
| `NEXT_PUBLIC_API_MOCKING` | 前端是否启用 MSW Mock（`off` 连真实后端） | 开启 |
| `NEXT_PUBLIC_API_BASE` | 前端请求的 API 前缀 | `/api/v1`（同源，Mock 模式保持默认） |
| `MINUTES_JWT_SECRET` | JWT 密钥（真实后端必填，≥24 位） | 无 |
| `MINUTES_ALLOW_INSECURE_JWT` | 本地无密钥临时放行 | `0` |
| `DATABASE_URL` | PostgreSQL 连接串 | 空（内存存储） |
| `REDIS_URL` | Redis 地址 | 空（进程内队列） |
| `ASR_PROVIDER` | 转写提供方 `local` / `aliyun` / `mock` | `local` |
| `LLM_API_KEY` / `LLM_MODEL` | 云端大模型摘要（默认通义 qwen-plus） | 空（演示模板） |

> ⚠️ Mock 模式下 `NEXT_PUBLIC_API_BASE` 必须保持默认同源 `/api/v1`，指向绝对地址会使请求绕过 Mock 直连后端导致全部失败。

## 四、启动 / 运行方法

### 方式 A：只跑前端（最快，零依赖，默认 Mock）

```powershell
cd apps/web
npm install
npm run dev
# 打开 http://localhost:3000
# 演示账号 demo@minutes.dev / minutes2026
```

### 方式 B：前端 + 真实后端（本地离线语音识别，无需 Docker）

终端 1 —— 启动后端：

```powershell
cd apps/api
$env:MINUTES_ALLOW_INSECURE_JWT = "1"   # 正式使用请设 MINUTES_JWT_SECRET
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

终端 2 —— 前端关闭 Mock 并指向后端（在 `apps/web/.env.local` 中设置）：

```
NEXT_PUBLIC_API_MOCKING=off
NEXT_PUBLIC_API_BASE=http://localhost:8000/api/v1
```

然后 `npm run dev`。接口文档：http://localhost:8000/docs

### 方式 C：Docker 全栈一键启动（含 PostgreSQL / Redis / MinIO / Worker）

双击仓库根目录 `一键启动-完整版.bat`，或手动：

```powershell
copy infra\.env.example .env    # 编辑 .env 设置 MINUTES_JWT_SECRET
docker compose -f infra/docker-compose.yml up -d --build
docker compose -f infra/docker-compose.yml run --rm api alembic upgrade head
docker compose -f infra/docker-compose.yml run --rm api python -m app.seed_db
# 打开 http://localhost:3000
```

### 常用命令

```powershell
cd apps/web
npm run build          # 生产构建
npm run typecheck      # 类型检查
npx playwright test    # E2E 测试（20 条）

cd apps/api
.\.venv\Scripts\python.exe -m pytest -q   # 后端测试（13 条）
```
